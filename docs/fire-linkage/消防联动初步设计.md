# 消防自动联动改造 —— 初步设计（V0.1 供评审，不作施工图依据）

> 现状：就地报警器（仅声报警）+ 雨淋阀人工开 + 消防泵人工启 + 非消防电源人工切。
> 目标：按探测点与火警等级**自动起泵、开阀、切非消防电源**；联动前必须确认**分区**；
> 误报可在确认窗口内**人工中止**；每次联动与处置**全程留痕可回溯**。

---

## 0. 必须先立住的合规边界（决定方案能不能验收）

1. **自动消防联动不是"PLC/SCADA 应用开发"项目，是消防设施工程**。系统构成、设备选型、
   逻辑、施工、验收必须由具备相应资质的消防设计单位出正式施工图，并按属地消防设计审查
   验收管理制度报审/备案；本文件只用于内部立项、需求对齐和招投标技术要求。
2. **核心设备必须是认证产品**：火灾报警控制器（联动型）、消防联动控制器、消防泵控制柜等
   应选用通过国家强制性认证（CCCF）的产品；**自研软件只能做监视、记录、报表、演练，
   不能取代认证控制器直接动作设备**。
3. **消防泵至少三条启动路径，且互相独立**（GB 50974 口径）：
   - **硬接线直接联锁启动**：出水干管压力开关 / 报警阀压力开关信号直接进泵控制柜，
     **不经任何软件、不能被人工中止、不能被联动控制器屏蔽**——这是泵在真实火灾
     下的兜底路径，永远处于战备状态；
   - 消防联动控制器联动启动（允许确认/延时逻辑）；
   - 消防控制室专线手动直接启动 + 泵房就地机械应急启泵。
   - **消防泵不允许自动停泵**，停泵只能由具有权限的人在现场/控制室手动执行。
4. **雨淋阀必须"与逻辑"防误喷**：同一防护区内 **2 个独立探测器信号同时成立**（或
   "探测器 + 手动火灾报警按钮"）才允许开启雨淋阀；雨淋/水幕通常配**感温**探测器，
   具体探测器类型与组合以 GB 50084、GB 50116 和设计单位选型为准。
5. **能"人工中止"的是确认窗口，不是喷水之后**。水系统一旦确认开阀/起泵即不再中止
   （气体灭火有 0–30s 延时窗口，那是另一套系统）。本方案因此把人工中止设计在
   **单信号"预警（L1）"阶段**——这是合规且实用的误报拦截点。
6. 消防控制室实行 **24h 双人值班，值班人员持消防设施操作员证**（GB 25506），
   设可直接报 119 的电话、应急广播、专线直接手动控制盘。

## 1. 总体架构：三层设备 + 三条独立控制路径

```
┌──────────────────────── 管理层 ────────────────────────┐
│  火灾报警控制器(联动型) + 消防联动控制器 + CRT图形显示   │
│  专线手动控制盘 │ 应急广播 │ 消防电话 │ 打印机 │ SOE记录 │
│  （可选）经只读网关 → flashsmelter 监视/审计/报表平台     │
└───────┬──────────────────────────────────┬──────────────┘
        │ 信号总线                          │ 专线硬线（手动直启/直停）
┌───────┴──────────────┐         ┌─────────┴──────────────────┐
│ 控制层：区域盘/模块    │         │ 泵控制柜 / 阀控制箱 / 配电柜 │
│  输入模块(探测器回讯)  │         │  （CCCF认证，就地手操保留）   │
│  输出模块(动作指令)    │         └─────────┬──────────────────┘
└───────┬──────────────┘                   │
        │ 总线          ┌──────────────────┼──────────────┐
┌───────┴──────────────────────────────┐   │  路径①：压力开关→泵柜  │
│ 现场层：感烟/感温探测器、手报、         │   │  （不经任何控制器）     │
│ 水流指示器、阀位/压力反馈、             │   └──────────────────────┘
│ 雨淋阀电磁阀、模块箱、消火栓按钮         │
└───────────────────────────────────────┘
```

**三条路径的分工（关键设计原则）：**

| 路径 | 触发源 | 经过软件？ | 可中止？ | 作用 |
|---|---|---|---|---|
| ① 硬接线联锁 | 压力开关等 | 否 | 否 | 真实火灾兜底，永远在线 |
| ② 联动控制器自动 | 两探测器与逻辑 | 是（认证固件） | L1 窗口可中止；确认后水系统不可中止 | 本项目新增的"自动" |
| ③ 专线手动 + 就地机械 | 值班员/泵房人员 | 否 | — | 任何自动系统失效时的人因兜底 |

flashsmelter 平台的定位：**通过只读/协议网关做状态汇聚、SOE、审计、报表与演练评分**，
不下发真实动作指令；真实联动逻辑全部落在认证的消防联动控制器里。

## 2. 分区模型（联动前必须知道"哪个区"）

参考 GB 50116 的报警区域 / 防火分区 / 探测区域划分，做三层映射：

- **报警区域 A-ZONE**：报警与显示的最小定位单位，建议与工艺布置贴合，例如
  `FS-FL-01`（闪速炉楼层-区域序号），与平台现有点位命名口径保持一致；
- **防护区 P-ZONE**：一套雨淋阀保护的范围，1 个或多个 A-ZONE 归到 1 个 P-ZONE
  （1 个 P-ZONE 对应 1 组阀、1 张启动逻辑表）；
- **联动分区 L-ZONE**：非消防电源切除、防排烟、广播、电梯等跨专业动作的作用范围，
  在联动逻辑表里按动作项分别指定（电源切除范围通常**大于**喷水区域，需工艺会签）。

每个探测器/手报在控制器点表中都必须带：`A-ZONE → P-ZONE`、位置文字、楼层平面图坐标。
控制器首报即按 A-ZONE 弹出区域名+平面图，CRT 闪烁定位——这就是"联动前确认是哪个区"。

> 跨区处置：两个不同 A-ZONE 报警且属于同一防火分区时，按本区火警升级处理；
> 分属不同防火分区时按多点火警处理，联动范围取并集，并提示值班员核实。

## 3. 火警等级、状态机与分级联动动作

### 3.1 等级定义

| 等级 | 名称 | 进入条件 |
|---|---|---|
| L0 | 正常监视 | — |
| L1 | 预警（可中止窗口） | 同一 A-ZONE 内**单个**探测器报警；或单点故障引发的疑似火警 |
| L2 | 确认火警 | 同区 **2 个独立探测器**与逻辑成立；或**手报**动作；或值班员手动确认 |
| L3 | 联动动作中/已喷放 | 阀已动作、泵已运行、电源已切（逐项带反馈跟踪） |
| L4 | 灭火后处置 | 火灾确认扑灭 → 停泵复位（人工）、排水、现场复位、事件归档 |
| A | 误报中止（终态） | L1 窗口内人工核实为误报，登记后中止 |

> 手报属于人工发出的"确认火警"信号，直接进 L2，不设可中止窗口。
> 试验/检修状态下的探测器信号只提示不联动，进入和退出均需审批登记（见 §6）。

### 3.2 状态机（可直接映射到现有 `StateMachine`）

```python
transitions = {
    "NORMAL":   {"ALERT"},                                   # L0
    "ALERT":    {"CONFIRMED", "ABORTED"},                    # L1：确认 or 误报中止
    "CONFIRMED":{"ACTUATING", "ABORTED"},                    # L2：仅气体类延时动作可撤回；水系统不可撤回
    "ACTUATING":{"DISPOSAL"},                                # L3：全部动作到位（或带故障完成）
    "DISPOSAL": {"NORMAL"},                                  # L4：复位归档后回监视
    "ABORTED":  {"NORMAL"},                                  # 误报登记闭环
}
```

与平台现有约定一致：跃迁由状态机判合法性，非法跃迁抛错并入审计；
同一火警事件全程用一个 `correlation_id`（建议 `INC-年月日-序号`）串起所有记录。

### 3.3 分级动作表（每一行在联动逻辑表 CSV 里实例化）

**L1 预警（单信号，可逆动作 + 抢时间）**

1. 控制器按 A-ZONE 声光/显示报警，CRT 定位区域与平面图，打印首报；
2. 值班员按消防电话/视频/派人**现场核实**，启动确认倒计时
   （倒计时时长由设计定，工业场所建议短，核实靠并行派人而非干等）；
3. 启动本防护区声光警报（区域范围内的就地警报，范围按设计）；
4. 停 **L2 动作前必须先完成的可逆准备**：电梯迫降首落（也可设计为 L2 动作，按设计定）、
   相关正压送风/排烟机进入预启动待命；
5. flashsmelter 侧推送预警、生成事件号、开始 SOE 记录。

**L1 窗口的人工处置（误报中止路径）**

- **手动确认**：值班员核实为真 → 一键确认，立即升 L2 执行联动（不等第二信号）；
- **误报中止**：核实为误报 → 选中止原因（设备故障/扬尘水汽/施工动火/其他）+
  工号 + 备注 → 状态转 ABORTED，**复位探测器并登记维修工单**；
- **超时未操作**：不自动喷水。保持报警并升级提示（向第二值班人/值班主管推送），
  直到第二探测器信号成立自动进 L2，或人工两选一落定。宁可催人，不可误喷。

**L2 确认火警（与逻辑/手报/人工确认触发，执行设计规定的全套联动）**

| 动作项 | 触发与规则 |
|---|---|
| 开启对应 P-ZONE 雨淋阀 | 同区 2 信号与逻辑；开阀后回读阀位/压力反馈，超时未反馈报故障 |
| 消防泵启动 | 联动启动 + 压力开关硬线直启双保险；运行/故障信号回读；1# 失败自动启 2# |
| 声光警报 / 应急广播 | 按疏散方案分区广播，组织人员疏散 |
| 非消防电源切除 | 按下文 §4 分级切除表执行；**切除顺序在电梯迫降之后** |
| 防排烟/防火卷帘/常开防火门 | 按 GB 50116 与暖通/建筑专业联动表执行 |
| 电梯 | 全部迫降首落、开门放人；消防电梯供消防员使用 |
| 工艺联锁（冶炼特有） | 紧急切断该区域燃油/燃气/氧气等危险介质——由工艺安全/ESD 逻辑负责，消防系统只发请求信号，**不越权动作**，两侧均留记录 |
| 119 | 值班员立即电话报警（系统可辅助拨号/弹窗预案，不能替代人工报警义务） |

**L3 动作跟踪**：每个动作项三态跟踪 `指令已发 → 反馈到位 / 反馈超时 / 失败`，
任一失败自动重试或启动备用设备（如备用泵），并在控制室醒目报警；
动作的"指令时间、反馈时间、执行人/自动来源"全部进 SOE。

**L4 灭火后处置**：现场确认熄灭 → 有权限人员手动停泵（无自动停泵）→ 关阀复位、
排水、恢复供电（送电前必须现场检查，供电恢复单独审批）、探测器复位、
填写处置记录（起火原因、出动、损失、暴露问题、整改项），事件归档。

## 4. 非消防电源切除策略（工业场景最容易出错的一项）

不能"一火警全切全厂"——冶炼装置上有些负荷断电本身会制造更大事故。按负荷分级做表，
**每一路由工艺、电气、消防三方会签**：

| 类别 | 示例 | 火警时策略 |
|---|---|---|
| A 立即切除 | 着火区普通照明（应急照明投入后）、空调、非消防电梯、装饰/办公电源 | L2 确认后切除 |
| B 延时/有序切除 | 需先完成停机顺序的工艺辅助负荷 | 按预设顺序延时切除 |
| C 保留（消防负荷） | 消防泵、应急照明、防排烟、消防电梯、消防控制室电源 | 双电源/柴油发电机保障 |
| D 工艺安全保留负荷 | 关键冷却、关键控制/仪表电源、ESD 电源 | 保留，由工艺安全论证并书面会签 |

切除必须有**分励脱扣 + 辅助接点反馈**，切除与恢复都进 SOE；恢复供电须单独授权。

## 5. 与 flashsmelter 平台的对接方式（沿用现有工程习惯）

| 本项目概念 | 对应现有设施 | 用法 |
|---|---|---|
| 火警事件状态机 | `machine.StateMachine` | NORMAL/ALERT/CONFIRMED/ACTUATING/DISPOSAL/ABORTED，非法跃迁拒绝并记账 |
| 联动/处置记录 | `audit.AuditLog`（追加型 JSONL，`correlation_id` 串联） | 报警、中止、确认、每路输出、反馈、故障、复位全部入库；拒绝类动作也入库 |
| 落盘 | `store.DDurableStore` / `DurableStore` | 事件状态、事件号游标崩溃恢复；但**安全证书级记录以认证控制器+打印机为准**，平台记录是第二份 |
| 组件解耦 | `ports.py` 结构化 Protocol | 定义 `DetectorPort / ValvePort / PumpPort / PowerPort / PanelPort`，演练时可注入模拟器 |
| 命名空间 | `ns.Namespace` | 消防域独立前缀，如 `fire/incident/...`，与工艺数据隔离 |
| 时间戳 | `runtime.Clock` | 全平台统一时钟；建议现场部署 NTP 主时钟，SOE 分辨率满足验收要求 |

边界再次强调：平台侧只做**只读监视 + 记录 + 演练模拟**；
`ValvePort/PumpPort` 在生产环境只接"回读"接口，动作指令物理上只由认证控制器/硬线发出。

## 6. 防误报与运维模式

- **误报中止**仅在 L1 窗口有效，必须：身份认证（工号/刷卡）→ 选择原因 → 备注 →
  自动生成维修工单（探测器脏污/故障必须闭环）；ABORTED 事件保留全部原始信号，不可删除。
- **隔离/屏蔽**：探测器清洗、动火作业、检修可临时隔离点/区，需审批（申请人、原因、
  起止时间），到期自动解除并提示；隔离期间 CRT 常驻醒目标识。
- **试验模式**：季度/年度试验走测试模式，输出只模拟不真喷（真喷试验单独审批、
  单独方案）；试验记录同样留存。
- **故障安全**：总线断、回路失电、阀故障、反馈丢失均在控制室声光报故障；
  故障期间硬线直启路径①不受影响。

## 7. 记录与追溯（SOE）要求

每条记录字段建议（与 `AuditEvent` 对齐扩充）：

`seq, at(毫秒级), correlation_id(事件号), zone(A/P/L), source(设备地址/工号),
action, target, outcome(ok/rejected/failed/timeout), auto_or_manual,
before_state, after_state, details, namespace`

至少覆盖：首报、每点报警/恢复、升级判定、人工确认、误报中止（含原因）、
每路联动指令与反馈、故障与重试、泵启停（含路径①②③来源）、阀开闭、
电源切除/恢复、隔离/解除、试验、复位、L4 处置记录。

留存要求：火灾自动报警系统运行及火警处置记录按 GB 25506 要求保存（纸质打印
即时留痕 + 电子记录备份，保存期限按规范执行，一般不少于 1 年；
建议涉火事件记录永久归档）。平台记录双副本（本地 + 上位机/服务器）。

## 8. 实施路线（建议顺序）

1. **现场勘测 + 需求冻结**：清点探测器、阀、泵柜、配电柜回路，确认 A/P/L 分区
   （三张 CSV 即此阶段产出）；
2. 有资质单位做正式设计，组织内部工艺/电气/安全会签（重点：电源切除表、工艺联锁边界）；
3. 消防设计审查/备案（按属地规定，冶金项目通常属于特殊建设工程范围，须报审验）；
4. 采购 CCCF 认证设备，消防设施工程专业承包单位施工，监理旁站；
5. 调试：先单点、后分区逻辑（与逻辑、防误喷）、再全联动；泵必须实测三条启动路径；
6. 验收 + 消防检测，档案归档；值班员持证培训 + 灭火疏散演练；
7. 平台只读网关和 SOE/报表可在 5–6 阶段并行接入，用模拟器先跑。

## 9. 待你确认的现场条件（影响正式设计选型）

1. 保护对象性质：闪速炉车间/油站/氧气站/电缆隧道/液压站等各区域分别是什么？
   （决定雨淋还是水喷雾/泡沫、探测器用感温还是感烟、是否有气体灭火）
2. 现有消防泵数量、功率、控制柜是否支持自动接口与机械应急启动？
   是临时高压还是稳压泵系统、有无高位水箱/气压罐？
3. 雨淋阀数量、口径、现在是电手动还是纯机械开阀？有无阀室？
